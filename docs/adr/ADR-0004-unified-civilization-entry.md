# ADR-0004 — نقطة الدخول الحضارية الواحدة (توحيد المسارات الخمسة)

- **الحالة:** مقبول (Accepted) — 2026-10-22
- **البنود:** R-W1-009 (يفك حجب R-W2-006 جزئياً وR-W3-014). يعتمد على R-F-003 (ADR-0001).

## السياق
جرد R-W1-009 أثبت خمسة مسارات متباينة لـ«الحضارة»:

| المسار | الكائن | الملاحظة |
|---|---|---|
| `agos_kernel.civilization` (K) | `CivilizationRuntime` (dataclass) + `get_civilization()` | **الأغنى**: كل الأنظمة الفرعية (معرفة/ذاكرة/دماغ/نواة/تنفيذ/تحقق/موافقة/حوكمة/تعاون/منظمات/ثقة). كان فيه `get_civilization()` نشر النسخة قبل التحقق من نجاح `initialize()` |
| `agos_kernel.platform_runtime` | `CivilizationPlatform` + `get_platform()` | منصة فوق الحضارة — لكنها كانت تنشئ **نسخاً موازية** لكل نظام فرعي بما فيها حضارة كاملة خاصة بها |
| `agos_kernel.v2` | `CivilizationPlatformV2` + `get_platform_v2()` | غلاف فوق المنصة — لكنه كان ينشئ منصة جديدة لا يستخدم `get_platform()` |
| `agos.civilization` (حزمة المنصة) | `CivilizationRuntime` (فئة ثانية بنفس الاسم) | نموذج تنظيمي (منظمات/مجالس) — بلا getter وبلا مستهلك إنتاجي |
| `agos_kernel.civilization_packs` | `CivilizationPack` | مكتبة حزم = **محتوى** (قوائم معرفات) لا محرك تشغيل |

الخلل الجوهري: خمس «حضارات» متوازية محتملة — وصول المستهلك من أي مسار يعطيه كائناً غير الذي يعطيه مسار آخر، والمنصة كانت تحمل داخلها حضارة كاملة موازية بأنظمة مكررة (حالة مزدوجة).

## القرار

### 1. نقطة الدخول الواحدة: `agos_kernel.civilization.get_civilization()`
المعتمد هو محرك الحضارة النووي `agos_kernel.civilization` — وهو الأغنى وموجود أصلاً. **لا تُضاف واجهة سادسة**؛ نقطة الدخول هي `get_civilization()` القائمة، وكل المسارات الأخرى تفوّض إليها:

| المسار | دوره بعد التوحيد |
|---|---|
| `platform_runtime` | تركيب فوق الحضارة المعتمدة: `platform.civilization is get_civilization()`، وحقول الأنظمة المشتركة (`knowledge/memory/brain/core/compiler/graph_runtime/parallel_executor/verification/approval/governance/collaboration/organization/trust`) **تفوّض إلى أنظمة الحضارة نفسها** — مصدر حقيقة واحد، لا حالة مزدوجة. أنظمة المنصة الخاصة (orchestrator/repository/crossdomain/healing/prediction/simulation/api) تبقى للمنصة |
| `v2` | غلاف فوق **المنصة المعتمدة نفسها**: `v2.platform is get_platform()` — لا منصة موازية |
| `agos.civilization` | واجهة توافق تنظيمية (منظمات/مجالس): `get_civilization()` مفوّضة إلى المعتمد، وخاصية `canonical` على النسخة تصل إليه. نموذجها التنظيمي يبقى كما هو (G2) — **ولا يُدّعى تزامن حالة المنظمات** بينه وبين النواة |
| `civilization_packs` | **محتوى لا محرك**: الكتالوج يُتاح عبر الواجهة المعتمدة (`list_civilization_packs()` و`get_pack_catalog()`) — إتاحة الكتالوج لا تعني تفعيل القدرات ولا إنفاذ السياسات |

### 2. دورة الحياة والملكية
- **الملكية:** الحالة الحضارية (المعرفة/الذاكرة/المنظمات/…) ملك الحضارة المعتمدة؛ المنصة وv2 تركيبان يفوّضان إليها ولا يملكان نسخاً.
- **النشر:** `get_civilization()` و`get_platform()` **لا تنشران نسخة فاشلة** — تُنشأ مرشحة، وإن فشلت التهيئة يُرفع `RuntimeError` بتشخيص باسم الفشل ولا يُخزَّن شيء، والمحاولة التالية تعيد المحاولة. (قبل هذا القرار كانتا تنشران ثم تتجاهلان فشل التهيئة — فشل صامت).
- **الفشل ينتقل عبر السلسلة كلها:** فشل النواة الداخلي فشل للحضارة (تُفحص نتيجة `core.initialize()` ولا يُختم ختم التهيئة إلا بنجاحها)، والمنصة تهيئ عبر الحضارة نفسها (`self.civilization.initialize()` بفحص النجاح) لا استدعاءً مباشراً للنواة، وفشل تهيئة المنصة ينتقل صراحة إلى غلاف v2 — لا يُبنى غلاف فوق منصة فاشلة.
- **التهيئة idempotent:** `CivilizationRuntime.initialize()` و`CivilizationPlatform.initialize()` تعودان فوراً عند التهيئة السابقة — إنشاء غلاف v2 أو منصة جديدة فوق حضارة مهيأة لا يعيد تهيئة النواة المشتركة (ختم الحضارة المشترك) ولا يمحو حالتها.
- **الإنشاء المعزول الصريح:** `CivilizationPlatform(civilization=...)` و`CivilizationPlatformV2(platform=...)` تقبلان اعتماداً صريحاً — للتركيب المعزول في الاختبارات دون المساس بالتجميع المعتمد. المنشئات القديمة بلا معاملات تعمل كما هي.

### 3. هوية مضمونة عبر كل المسارات
أي طريقة وصول — `agos_kernel.civilization.get_civilization()` أو `get_platform().civilization` أو `get_platform_v2().platform.civilization` أو `agos.civilization.get_civilization()` — تعيد **الكائن نفسه** (`is`). الاختبارات تثبتها في مفسّرات جديدة بترتيبات استيراد مختلفة، مع بقاء الفصل المقصود بين حزمتي الحضارة (ADR-0001: النواة `agos_kernel.*` والمنصة `agos/`): التوحيد بالتفويض لا بطمس الحزمتين.

### 4. خارج النطاق (موثق صادقاً)
- **تشغيل كل ملفات الحضارة (99 ملفاً) ورفعها إلى L3** — معيار R-W3-014، ليس هذا البند.
- **توحيد ذكاء المستودعات** (`capabilities` + `rie` v2 + `civilization/capabilities/repository_analysis` + …) — R-W2-006، محجوب سابقاً على هذا البند.
- **تزامن نموذج المنظمات** بين `agos.civilization` والنواة — لم يُنفَّذ ولم يُدّعَ؛ نموذج المنصة توافق تنظيمي فقط.
- **تفعيل محتوى الحزم** (تثبيت قدراتها/إنفاذ سياساتها) — الحزم كتالوج محتوى فقط.

## العواقب
- وصول أي مستهلك من أي مسار إلى الحضارة نفسها — لا مسار موازٍ ضعيف.
- تغيير سلوك `get_civilization()` عند فشل التهيئة: كان يعيد نسخة معطلة بصمت، الآن يرفع تشخيصاً — فشل صامت صار معلناً (المادة 6).
- المنصة لم تعد تنسخ أنظمة الحضارة — استهلاك الذاكمة أقل وحالة واحدة.
