# ADR-0005 — توحيد ذكاء المستودعات: خط واحد والبقية واجهات

- **الحالة:** مقبول (Accepted) — 2026-10-22
- **البنود:** R-W2-006 (يفك حجب R-W2-012 وR-W2-013). يعتمد على R-W1-009 (ADR-0004) وR-F-006 (ADR-0001).

## السياق
جرد R-W2-006 أثبت خمسة مسارات متباينة «لذكاء المستودعات»، كلٌّ بمسحه الخاص
وأحياناً بتنفيذ متوازٍ لنفس الدلالات:

| المسار | الكائن | ملاحظة |
|---|---|---|
| `agos_kernel.capabilities` | `RepositoryAnalysisCapability` | خط قدرة المهمة (clone→read→detect→DNA) — كل عمل W2 الأخير هنا، يفوّض الكشف إلى `stack_detection` (المصدر الواحد) |
| `rie` (حزمة المنصة) | `RepositoryIntelligencePipeline` + `DNAGeneratorV2` | بنية v2 (عقود/كاشفون) — بلا مستهلكين |
| `civilization/capabilities` | `RepositoryAnalyzer` (repository_analysis) + `RepositoryDNA` (repository_dna) | مستهلكون إنتاجيون حقيقيون (foundation/civilization_engine/workflows) — لكن بمسح خاص وتنفيذ موازٍ لعدّ اللغات والأسطر |
| `agos_kernel.intelligence` | `RepositoryAnalyzer` (repository/) + `ProjectDNAGenerator` | مستهلك حقيقي: اختبارات W2 تعبره؛ كان يمسح القرص 8 مرات لكل تحليل (os.walk لكل مرحلة) |
| `agos_kernel.repository` | `MultiRepositoryRuntime` + محلل رفيع | سجل/مزامنة/فرق متعدد المستودعات — شاغل مختلف، ليس تحليل محتوى |

الخلل الجوهري: خمس عمليات مسح مستقلة لنفس المحتوى — نتائج قد تتفق أو تختلف
حسب المسار، وسلوكيات خطأ وصمت مختلفة، وحدود قراءة مختلفة.

## القرار

### 1. الخط الواحد: خدمة مشتركة داخل `capabilities`
`agos_kernel.capabilities.analysis_service.RepositoryAnalysisService` — نقطة
التحليل الواحدة:

- **النتيجة المشتركة `SharedAnalysis`:** فهرس ملفات واحد (مسار/حجم/امتداد/
  أسطر)، المحتوى المقروء، أسباب عدم القراءة (`too_large`/`binary`/`symlink`/
  `read_error` — الملف الكبير أو الثنائي ليس ملفاً فارغاً)، إحصاء لغات ملفات
  الشيفرة من `stack_detection.language_weights` (المصدر الواحد، مرجّح بالأسطر)،
  خريطة الملفات البيانية وتقرير المكدس الكامل من `stack_detection.detect_stack`.
- **مصدران فقط:** `analyze_url(url, branch)` — استنساخ وقراءة عبر المزوّد القائم
  (سياسة R-W2-004/005 نفسها)، والحقائق تكتمل في الذاكرة **قبل** تنظيف المستنسخ؛
  و`analyze_path(path)` — مجلد محلي مباشرة: بلا استنساخ ولا شبكة ولا افتراضات
  git ولا حذف لمجلد المستخدم ولا تخزين مؤقت (لا بصمة تغيّر معتمدة بعد).

### 2. البقية واجهات — إسقاطات فوق الحقائق، لا تنفيذ موازٍ
| المدخل القديم | دوره بعد التوحيد |
|---|---|
| `RepositoryAnalysisCapability.execute` | إسقاط DNA النواة من `analyze_url` (الكاش بمفتاح الالتزام والرسم المعرفي كما هما — R-F-008/R-W2-008) |
| `civilization/capabilities/repository_analysis` | إسقاط `RepositoryInfo` من `analyze_path` — تصنيفه القديم نفسه (JSON/YAML/Markdown لغات — مقياس مختلف عن لغات الشيفرة، إسقاط صريح لا يُسقط صمتاً) |
| `civilization/capabilities/repository_dna` | البصمة تُحسب من فهرس الخدمة ومحتواها (لا مسح قرص ثانٍ) |
| `intelligence/repository/analyzer` | كل الاكتشافات إسقاطات فوق فهرس الخدمة ومحتواها — لا `os.walk` لكل مرحلة؛ ميزاته الفريدة (أنظمة البناء/قواعد البيانات/الطوابير/…) محفوظة كمراحل فوق الحقائق |
| `intelligence.dna.ProjectDNAGenerator` | **مجمّع فوق جينومات** (مستهلك لا محلل) — كما هو |
| `rie.RepositoryIntelligencePipeline` | الجلب والقراءة عبر `analyze_url`؛ `normalized` يُبنى من الحقائق والكاشفون يعملون فوقها في الذاكرة؛ `DNAGeneratorV2` إسقاط فوق الميزات كما هو |
| `repository/runtime` | **خارج خط التحليل** — سجل/مزامنة/فرق (شاغل مختلف)، يبقى كما هو |
| `foundation.analyze_repository` | تركيبه كما هو؛ محلله (`repository_analysis`) يفوّض |

### 3. سياستات المسح لكل واجهة — توحيد التنفيذ لا فرض سياسة واحدة
كل واجهة تحتفظ بسياستها القديمة بالضبط (استثناءاتها، تصنيفها) وتُمرَّر للخدمة
(`ScanPolicy`) — التوحيد في المسح والفهرس والمراحل، لا في خلط المقاييس.

### 4. توحيدات سلوكية موثقة (فروق مقصودة عن السلوك القديم)
1. **حجم المستودع (civ):** المجلدات المستثناة (node_modules وأمثالها) لم تعد
   تنفّط الحجم (كانت تدخله لأن فحص الاسم وحده لم يكن يستثني محتواها).
2. **بصمة الشيفرة (civ DNA):** ملفات .py داخل المجلدات المستثناة لم تعد تُهشّ
   (نفس السبب — فحص الاسم كان يمّرها).

وما عداه **محفوظ بالضبط** — سياسة قارئ rie القديمة هي سياسة النواة نفسها
(R-W2-004/005) فلا فرق هناك أصلاً. والمحفوظات المُثبتة بالاختبار (مقارنةً
بالحساب القديم نفسه لا بمجرد الوجود): بصمة الملفات الكبيرة (>1MB) محفوظة
(هاش تدفقي أثناء المسح: فك utf-8 صارم ثم توطين الأسطر كقراءة النص القديمة
ثم هاش النص — فاقد الترميز يُتخطى كما كان)، ومقاييس أسطر الملفات الكبيرة
والثنائية محفوظة (تصنيف تدفقي فوق فك ignore بدلالات قراءة النص القديمة —
توطين \r\n/\r وتقسيم \n — والملف المُهشّ يُصنّف في المرور نفسه، والسطر
العملاق ذاكرة محدودة بعدّ محفوظ)، وأسطر اللغات مفصولة عن مقاييس التصنيف
(أسطر المحتوى من قراءة replace كما كانت قراءة اللغات؛ مقاييس التصنيف من
فك ignore كما كانت المقاييس تقرأ)، وكشف قواعد البيانات/الطوابير في الملف
الكبير ببحث تدفقي عبر الخدمة بدفعات ثابتة الذاكرة وتداخل حدود الدفعات —
بلا سقف وبلا فتح روابط رمزية (النتيجة كالقديم: الكلمة تُكتشف أيا كان موقعها)،
والفرع الفعلي بعد تراجع clone_safety يُعكس في الحقائق لا المعامل، وأخطاء
الوصول أثناء المسح نقص معلن (تحذير مسمى بالمسارات من الخدمة نفسها — يرثه
كل مدخل فوقها — + ``scan_errors``) لا نجاح بنصف فهرس، وروابط .py الرمزية
لا تُقرأ حتى للكشف (R-W2-005).

### 5. خارج النطاق (موثق صادقاً)
- **جينوم القدرات CGP** (R-W2-012) و**خط معالجة المستودعات RPP** (R-W2-013) —
  بنود لاحقة فوق هذا الخط، لم تُبنَ هنا.
- **توحيد تحليلات العمق** (جودة الشيفرة/الأمان/المعمارية في civ/capabilities)
  — تحليلات مختلفة لا «ذكاء مستودعات»، بقيت كما هي.
- **تخزين مؤقت لمصدر path** — يحتاج بصمة تغيّر معتمدة؛ لم تُدّعَ.
- **محلل `repository/runtime` الرفيع** — بيانات وصفية لا تحليل محتوى.

## العواقب
- مسح واحد وفهرس واحد لكل الواجهات — لا نتائج متنافرة بين المسارات.
- أخطاء القراءة موثقة بأسبابها لا ملفات فارغة، والفشل معلن لا صامت.
- كل شكل إرجاع قديم محفوظ بالضبط (اختبارات الأشكال القديمة تثبته) — المستهلكون
  لا يغيرون شيئاً، والفروق المقصودة موثقة أعلاه.
