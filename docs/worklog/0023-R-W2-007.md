# 0023 — R-W2-007: القدرات السبع الحقيقية

- **التاريخ:** 2026-10-21
- **البند:** R-W2-007 (DONE). يعتمد على R-W2-002 (الاعتماديات بقيد الإصدار — مدخل OSV).
- **معيار القبول:** «كل قدرة باختبار تكامل حقيقي؛ لا نتيجة إيجابية بلا فحص».

## الدراسة: ست كعبات تعيد نتائج ثابتة
`capabilities/foundation_extra.py` (القدرات 14–20) كانت تعيد قوماً فارغة ثابتة: `secrets_found: 0` و`risk_level: "low"` بلا أي فحص، و`license: "unknown"` و`compatible: True` بلا قراءة ملف، و`has_docker: False`… إلخ. علاوة على فجوة بنية: هذه الأصناف لم تكن `ICapability` أصلاً فلم تكن مسجلة في السجل ولا تُحل بها مهمة.

## التصميم
**مصدر واحد** بقي الملف نفسه (`foundation_extra.py`)، والكشف القائم فوُضّ إليه لـ`stack_detection` (لغات/أطر/اعتماديات/ملفات تكوين). مبادئ نُفّذت في السبع جميعاً:

1. **مسار بيانات موحد** `_acquire`: `{"url"}` (استنساخ عبر `clone_safety` مع تنظيف مضمون عند الفشل) أو `{"repo_path"}` أو `{"snapshot"}` أو `{"files"}`. والتمييز الملزم: `content=None` تعني «لم يُقرأ»، والفارغة «قُرئ ووجد فارغاً».
2. **لا نتيجة إيجابية بلا فحص**: كل نتيجة تحمل دليلها (ملف/سطر/قاعدة/عبارة/بسط-مقام)، وكل فحص تعذر يُعلن حالته.

## التحقق
- **`tests/test_seven_capabilities.py` (52 اختباراً):** لكل قدرة إيجابية وسلبية ومدخل معطوب، عبر المسارات الحقيقية (`url`/`repo_path`/مهمة كاملة تُحل بالاسم وتُنفّذ).
  - **OSV ثلاث طبقات:** دالة محقونة (حتمية بلا شبكة)، وطبقة HTTP فعلية بمخدم محلي يرد استجابة `querybatch`، واختبار حي مرجعي (requests 2.19.1) — **نجح فعلياً** مع الشبكة، ويؤكد المعرف المرجعي تحديداً (`GHSA-x84v-xcm2-53pg` = CVE-2018-18074).
  - **حالات دلالية حرجة:** فشل OSV لا يعطي `low` (medium)، والنظيف الكامل وحده `low`، والنطاقات غير المفحوصة معلنة، والسر الخام لا يظهر في JSON كاملاً، و`${VAR}` placeholder لا يُحسب سراً، وMIT في README بلا LICENSE ليست ترخيصاً، و`compatible` غير مفترض.
- **جولة مراجعة مستقلة ثانية** كشفت وأغلقت فجوات أدق:
  - **عقد قديم محفوظ:** قائمة ملفات مباشرة، و`RepositorySnapshot` بلا غلاف، و`{"snapshot": {"files": {path: content}}}` — كلها مقبولة الآن؛ و`version = "1.0.0"` صفة صف محفوظة على السبع.
  - **OSV محقّق البنية:** استجابة ليست قائمة أو أقصر من الاستعلامات ← حالة `partial` معلنة (لا نجاح صامت)، والتحديد صار **واعياً بالنظام البيئي** (في pypi الاسم المجرد ليس تثبيتاً، وفي Cargo.toml الـ`1.2.3` تعني `^1.2.3` لا تثبيتاً).
  - **الفحص الجزئي معلن:** ملفات لم تُقرأ أو أخطاء تحليل ملفات الاعتماديات ← الخطورة `medium` لا `low` (اختباران)، والفجوات تُمرّر لاستخراج المعرفة.
  - **الترخيص بدليل أدق:** BSD-2/3 ببند المنع لا بالتفاف الأسطر، وGPL بعبارة «or later» الموجودة فعلاً، والمرشحون كلهم يُفحصون (COPYING مجهول لا يحجب LICENSE معروفاً — معلنون في `license_candidates`)، والمعلن من `pyproject` بتحليل TOML فعلي من `[project]` فقط (لا `[tool.*]`)، و`package.json` قائمة ← ليس كائناً.
  - **البنية التحتية:** دليل SDK من قائمة الاعتماديات الفعلية فقط (ذكر boto3 في README ليس دليلاً — اختبار سلبي)، وأسماء مزودي TF مطابقة فعلياً (google/azurerm)، والكشف في ملفات `.tf` فقط.
  - **التوثيق:** نطاق العدّ معلن ومختبر (الدوال المتداخلة داخل دالة تفصيل تنفيذي لا تُحصى، والخاص لا يُحصى)، وملفات Python المعطوبة تُعلن في `python_parse_errors` ولا تُطمس.
  - **التكوين:** JSON الفارغ مقروء ويُرفض (لا يُتخطى)، ووحدة المدخلات: `.env` عبر `files` كالموجودة على القرص، والدلالة وجودٌ لا اتباع git.
  - **الملخص:** `primary_language` صريح في مخرج DNA (كسر التعادل بالملفات قد يخالف أول القائمة المرتبة بالأسطر فالاسم — مختبر).
- **اختبار الطفرة (7 طفرات، كلها كُشفت):** التنقيح معطل ← فشل؛ partial→completed ← فشل؛ بند المنع BSD معطل ← فشل؛ docstrings دوماً موثقة ← فشل؛ فشل OSV→low ← فشل؛ إسقاط الفجوات ← فشل؛ وترتيب البصمة (طفرتان: بلا sort_keys وsorted→list) — **متكافئتان سلوكياً**: الترتيب يُطبّع في المصدر نفسه (`language_weights` تُرجع قاموساً مرتباً) — فالبصمة مستقلة للترتيب بالتصميم لا بحيلة، وهذا موثق لا مخفي.
- **فحص حي على مستودع حقيقي (psf/requests عبر GitHub):** SecurityScan اكتمل: `risk: high` مع **4 مفاتيح خاصة هي شهادات mTLS اختبارية موقّعة ذاتياً** تحت `tests/certs/` (عهد اختبارية لا اعتمادات حقيقية — النتيجة «سر محتمل» بطبيعتها لا مؤكدة)، و6 ملفات غير مقروءة معلنة، وOSV الحي اكتمل (0 ثغرات على المثبتات، 24 قيداً نطاقياً معلناً)، وLicenseAnalysis: `Apache-2.0` من النص (الصحيح فعلاً).
- **المجموعة الكاملة:** كانت 439 + 16 متخطى (لانقطاع الشبكة وقتها)؛ الآن **507 / 0 / 0 / 0** كاملاً بلا تخطٍّ (الشبكة عادت فاختبارات المستودعات الحية كلها تنجح).
- **أدوات التدقيق كلها خضراء** ورمز الخروج مفتوح لكل أمر (بلا إخفاء بـ`| tail`)، وبوابة الحوكمة فُحصت على الدفعة المُرحّلة فعلاً.

## تغيّر في السلوك (مقصود)
- **القدرات السبع تُسجل في السجل وتُحل بها المهام بالاسم** (لم تكن مسجلة أصلاً).
- **نتائجها مشتقة من الفحص** لا ثابتة: `secrets_found` و`risk_level` و`license` و`has_docker`… كلها من محتوى فعلي، مع حقول دليل وحالة لكل فحص.
- **فشل الفحص لم يعد يبدو نجاحاً**: `osv_status` و`gaps` و`compatible: None` تعلن الحقيقة.

## حدود معروفة (موثقة لا مخفية)
- الأسرار المكتشفة «محتملة» (تطابق نمط) — لا تحقق من صلاحية الاعتماد.
- OSV يفحص المثبتات بدقة فقط؛ القيود النطاقية معلنة غير مفحوصة.
- تراخيص الاعتماديات لا تُجمع (تحتاج قاعدة بيانات خارجية — خارج البند)، وتوافقها معلن «غير مفحوص».
- فحص docstrings لـPython فقط (النطاق معلن في `doc_coverage_scope`).
- KnowledgeExtraction يعمل على النتائج المعطاة له فقط؛ غياب نتيجة قدرة يُعلن فجوة.
