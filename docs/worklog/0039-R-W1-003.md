# سجل العمل 0039 — R-W1-003: توحيد التنفيذ (محرك تنفيذ واحد)

**البند:** توحيد **التنفيذ** (`execution`(K), `pipeline`, `execution-context`,
`context`, `agos.execution`, `fabric.execution`, `cloud_execution`) — ADR +
محرك تنفيذ واحد. التبعية R-F-005 (منجزة).
**الوثيقة:** [ADR-0008](../adr/ADR-0008-unified-execution.md).
**المرجع عند البدء:** `c0f286a` (HEAD). لا شيء من هذا البند ملتزم قبلاً.

## 1) المسح — مصفوفة بالأدلة

## 2) عقد ADR-0008 (خلاصة)

- **النواة المشتركة:** `ExecutionEngine` (الموجود) — **محرك الاستدعاء
  الوحيد**. واجهة متزامنة جديدة `invoke_sync(func, *args, **kwargs)` ←
  `InvocationOutcome(value, error)`: استدعاء واحد بلا مهلة ولا إعادة؛
  النجاح = `error is None` (القيم الزائفة مشروعة)؛ يلتقط `Exception` فقط
  (استثناءات التحكم تمر)؛ يرفض دوال الكوروتين والكوروتينات/الـawaitables
  غير المنفذة صراحةً دون تشغيل (الـcoroutine الفعلي وحده يُغلق منعاً لتحذير
  عدم الانتظار، وأخطاء الإغلاق تبقى في المخرج)؛ يعمل داخل حلقة أحداث
  دائرة. الواجهة غير المتزامنة (`execute`) بلا تغيير.
- **التنسيق الحي:** `ExecutionPipeline` طبقة تنسيق حية (حل/خطوات/أحداث/دليل
  قرار) تمرر استدعاء القدرة إلى النواة: معامل رابع اختياري
  `execution_engine=None` (كسول إلى `get_engine`)؛ التوجيه
  `outcome = engine.invoke_sync(capability.execute, mission.parameters)`
  والخطأ يُرفع كما هو. سياسة المسار الحي (استدعاء واحد) بلا تغيير.
- **لا توحيد قسري** لأنواع النتائج/السياقات/الرسوم؛ ولا منفذ رسوم/عامل
  سحابي مُختلق في هذا البند.
- **الإعادة الاستخدام الصادقة:** كل واجهة صورية سابقة تعلن `not_executed`
  بمسوغ مسمى بدل ادعاء الإكمال (تفصيل §3).
- **عقد `handler(context)` جديد معتمد:** بما أن لا عقداً قائماً في الشجرة،
  اعتُمد في ADR-0008 عقداً إضافياً جديداً موثقاً: المخرج dict يمر كما هو
  وغير dict يُلف في `{"result": ...}`؛ والفشل (استثناء الحامل) يُترجم
  فشلاً صريحاً؛ وغياب الحامل فشل صريح لا نجاح وهمياً.

## 3) التنفيذ

1. **engine.py**: `import inspect` + `InvocationOutcome` (dataclass:
   value/error + خاصية ok) + `invoke_sync` بعقد §2.
2. **pipeline/__init__.py**: المعامل الرابع الاختياري + التوجيه عبر النواة.
3. **parallel.py** (إعادة كتابة): `_begin_attempt` (إعادة ضبط موحدة لحقول
   المحاولة الجارية: result/error/started_at/completed_at قبل أي تحليل أو
   منع أو عودة مبكرة في الطريقتين)؛ `_invoke_original` (استدعاء الأصل عبر
   النواة؛ التبعية الفاشلة تمنع التابعة؛ غياب func فشل صريح)؛
   `_sync_scheduled_copy` (الحالة والطوابع والنتيجة والخطأ — بعد كل مسارات
   الخروج في الطريقتين)؛ `execute` (تحليل الدورات الحقيقي محفوظ؛ الجاهزية
   **إيجابية** من نتائج الاستدعاء الحالي وحده — لا سجل مجدول قديم؛ تنفيذ
   تسلسلي موثق؛ كل مهمة تخرج بمخرج صريح)؛ `execute_pipeline` (تحقق إيجابي
   قبل الاستدعاء: التبعية يجب أن تكون اكتملت في نطاق هذا الاستدعاء —
   فالتابعة التي تمر قبل سابقتها لا تعمل).
4. **capability_runtime**: `_execute_capability` — غياب الحامل فشل صريح؛
   الحامل القابل للاستدعاء يمر بالنواة بعقد `handler(context)` المعتمد.
5. **الواجهات الصورية ← صادقة**: `fabric.execution` ←
   `{"status": "not_executed", ...}`؛ `execution.fabric` ←
   `ExecutionUnit(status="not_executed", evidence=[reason])`؛
   `workflow_runtime.execute_workflow` ← `{'status': 'not_executed'}` بلا
   تعديل حالة (خيار المراجعة). `cloud_execution` الصادق لم يُمس.

## 4) جولات المراجعة (عشر جولات — التصحيحات الحاسمة)

1–6. التخطيط؛ رفض المسح الأولي (أدلة غير كافية)؛ بوابة اعتماد المسح؛
   اعتماد ADR-0008؛ اعتماد الدفعة الأولى (النواة + الأنبوب + ParallelExecutor
   + تصحيحات الصدق)؛ مراجعة التوسعة.
7. **ثلاث فجوات مانعة:** (أ) تحقق تبعيات `execute_pipeline` كان يتجاهل التبعية
   غير الموجودة في النتائج بعد — التابعة المارّة قبل سابقتها كانت تعمل؛
   صار التحقق إيجابياً (اكتمال التبعية في نطاق الاستدعاء الحالي شرط قبل
   الاستدعاء)؛ (ب) بقايا المحاولة السابقة (نجاح ثم فشل يترك نتيجة/خطأ
   قديمين) — إعادة ضبط موحدة؛ (ج) عقد `handler` كان «تكييفاً مؤقتاً» —
   حُسم عقداً جديداً موثقاً في ADR.
8. **إعادة الضبط غير شاملة:** `started_at` لم يكن يُمسح؛ فرع الدورات المبكر
   لا يعيد الضبط ولا يزامن نسخة المجدول؛ `execute_pipeline` لا يزامن مهام
   سجلها `execute` سابقاً (إحصاءات بنجاح قديم)؛ `_sync_scheduled_copy` لا
   ينقل `started_at` — أُصلحت جميعها: إعادة الضبط قبل أي تحليل، والمزامنة
   بعد كل مسارات الخروج في الطريقتين.
9. **تحصين الاختبارات:** هوية السياق (`is` لا مساواة)، فحص نسخة المجدول
   مباشرة (الحقول لا العدادات فقط)، وkwargs غير الفارغة في وضع الأنبوب
   (نجاحاً وفشلاً).
10. **الاعتماد النهائي:** لا مانعاً خوارزمياً إضافياً — الإغلاق.

## 5) الاختبارات

`tests/test_execution_unification.py` — **40 اختباراً**: توصيف القائم (10)،
عقد `invoke_sync` (الزائفة المشروعة، استثناءات التحكم تمر، رفض
الكوروتينات/الـawaitables بلا تسريب، حلقة الأحداث الدائرة، إغلاق
الكوروتين العنيد)، التوجيه عبر النواة بإثبات مميّز (نواة زائفة بحارس
يُرفع إن استُدعي خارجها — هوية الدالة وargs/kwargs وعدد الاستدعاءات،
نجاحاً وفشلاً، في كل واجهة: الأنبوب و`ParallelExecutor.execute` و
`execute_pipeline` و`CapabilityExecutor` — وهوية السياق نفسه في القدرة)،
الربط بالنواة الحقيقية الافتراضية (استدعاء واحد بلا إعادة)، صدق
ParallelExecutor (الأصول تُستدعى فعلاً، الوهم فشل صريح، التابعة لا تعمل
بعد فشل السابقة، غياب func، الوضعان)، الجاهزية الإيجابية (التابعة قبل
سابقتها، إعادة استخدام المنفذ عبر الاستدعاءات)، إعادة ضبط المحاولة
(نجاح↔فشل بالاتجاهين، الدورة بعد نجاح، غياب func بعد نجاح، التبديل بين
الطريقتين — الأصل ونسخة المجدول معاً). **المجموعة الكاملة: 973 passed /
0 failed / 0 skipped** (862+71+40) بلا انحدارات (`set -o pipefail` —
PIPESTATUS 0 0).
